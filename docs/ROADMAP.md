# Proposed roadmap

Phases describe possible increments, not committed dates or approved architecture. Each phase should be revisited after discovery and technical findings.

| Phase | Focus | Suggested exit evidence |
| --- | --- | --- |
| 0 — Documentation and product discovery | Establish project scope, interview prospective users and contributors, verify comparisons and candidate simulation licenses. | Prioritized MVP scenarios and documented findings. |
| 1 — Architecture and technical foundations | Test static builds, origin isolation, manifest design, and isolated build/publish controls; decide stack and hosting. | Reviewed security model and recorded decisions backed by small feasibility probes. |
| 2 — UI/UX and catalogue | Design accessible navigation, topic structure, and a scientific explanation template. | A reviewable catalogue experience with representative content. |
| 3 — Initial playable simulations | Integrate licensed, feasible candidates with parameter controls, explanations, references, and source links. | Browser-tested simulations with verified provenance and documented limitations. |
| 4 — Automated simulation integration pipeline | Add isolated, pinned builds, validation, review gates, and artifact publication. | Repeatable integration with security checks and failure handling. |
| 5 — Community contributions | Document submission, review, attribution, maintenance, and moderation processes. | A contributor can submit a simulation through a reviewed path. |
| 6 — Production hardening and deployment | Test accessibility, performance, security, observability, recovery, and hosting operations. | Production readiness criteria met and deployment approved. |

The order may change: a small integration feasibility probe belongs in Phase 1 before committing to the catalogue architecture. Automation and community publishing should follow a demonstrated secure manual path.
