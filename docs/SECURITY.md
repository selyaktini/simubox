# Security model and limitations

The trusted catalogue, player runtime, future external build environment and future credentialed publication environment are distinct trust zones. This MVP only builds original first-party source. It does not build or serve external candidate artifacts.

The player iframe grants only `allow-scripts`; it omits `allow-same-origin`, forms, popups, downloads, top navigation and other capabilities. Opaque origins prevent direct access to catalogue storage and DOM, but can break module loading, workers and storage. The first-party development server sends a restrictive CSP and `nosniff`. The production output is static files; equivalent hosting headers and a separate external artifact origin must be configured and tested before public deployment. A sandboxed iframe alone is not a production security review.

Future external build jobs must use disposable containers or equivalent isolation, restricted network and filesystem, resource limits, no host home, no SSH agent, no deployment credentials and no repository write token. Review locked dependencies, build scripts, licensing and artifact contents; reject traversal, active HTML outside the intended entry, external fetches and unexpected assets. Publication must consume a validated immutable artifact in a separate credentialed job. Each external revision must receive origin, CSP, permissions and browser compatibility review. The first-party player uses only fixed `simubox:ping` and `simubox:ready` messages, with a simulation ID on the ready signal. The parent checks the exact frame window, opaque `null` origin, message type and simulation ID; it never interprets arbitrary payloads or sends sensitive data to the player.
